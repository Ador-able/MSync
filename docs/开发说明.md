# 开发说明

## 环境与启动

支持 Windows x64。需要 Rust stable MSVC、Windows SDK/C++ 构建工具和 Node.js 22.12 及以上版本。离线设备模拟还需要 Git for Windows 自带的 Bash，打包脚本使用 PowerShell 7。

开发运行使用本机已安装的 WebView2；绿色包使用随包固定运行时。

将官方 [Android Platform-Tools](https://developer.android.com/tools/releases/platform-tools) 解压到 `runtime/adb-download/platform-tools`，然后运行：

```powershell
npm ci
npm run desktop
```

`tools/dev.ps1` 设置 ADB 路径，构建前端，再通过 Cargo 启动桌面程序。

## 验证

```powershell
cargo fmt --all -- --check
npm run build
cargo test --workspace --locked
cargo clippy --workspace --all-targets --locked -- -D warnings
```

设备模拟通过 Git Bash 执行设备端命令，结果写入 `target/adb-sync`：

```powershell
$env:MSYNC_TEST_BASH = '本机 Git/bin/bash.exe 的完整路径'
cargo run -p msync-core --example adb_sync_test --locked -- --simulated
cargo run -p msync-core --example adb_sync_test --locked -- --simulated --ignore-rules
cargo run -p msync-core --example adb_sync_test --locked -- --simulated --filename-errors
```

构建桌面程序和测试驱动后，可以运行界面流程验证，保持上述 Bash 环境变量可用：

```powershell
cargo build -p msync-desktop --locked
cargo build -p msync-core --example adb_sync_test --locked
node tools/ui-smoke.mjs --simulated
```

界面验证的设备及选目录对话框由测试提供。运行期间不要重编译测试驱动。

## 真机验证

`adb_probe` 只读探测目录；`adb_sync_test --write-test` 在指定父目录下创建 `MSync验证-<UUID>` 测试目录：

```powershell
$env:MSYNC_ADB_PATH = (Resolve-Path 'runtime/adb-download/platform-tools/adb.exe').Path
cargo run -p msync-core --example adb_probe -- '设备序列号' '/storage/emulated/0/工作文件'
cargo run -p msync-core --example adb_sync_test -- --write-test '设备序列号' '/storage/emulated/0/Documents'
```

设备测试范围见 [验证记录](验证记录.md)。

## 图文说明

Word 使用说明由 `tools/build-user-guide.py` 生成，需要 Python、Pillow、python-docx 和 Windows 微软雅黑字体。截图使用实际 Release 桌面程序，需要单独准备已授权的测试设备：

```powershell
cargo build --release -p msync-desktop
node tools/capture-guide.mjs --serial '设备序列号'
python tools/build-user-guide.py
```

截图工具在平板共享存储下新建带时间标识的演示目录，并向其中同步示例文件。`--folder-guide` 只查看设备上已有的“工作文件”目录。截图输出到 `target/manual`，Word 文档输出到 `docs/MSync 图文使用说明.docx`。

## 离线打包

准备微软 x64 [Fixed Version WebView2](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/distribution)、官方 Platform-Tools 和 [7-Zip 命令行程序](https://www.7-zip.org/download.html)。将 `7zr.exe` 放入 `runtime/7zip`，或用 `-SevenZipPath` 指定现有程序。

打包还要求 `runtime/usb-driver/usb_driver` 中存在匹配首次连接工具的驱动，脚本会检查驱动目录和两个签名目录文件（`.cat`）。驱动硬件范围由 `tools/prepare-device.ps1` 确定，分发前应在目标设备验证。

```powershell
./tools/package.ps1 -RuntimePath 'WebView2 解压目录' -AdbPath 'Platform-Tools 解压目录'
node tools/ui-smoke.mjs '生成目录/MSync.exe' --simulated
```

脚本构建前端和 Rust Release，生成文件哈希清单，收集依赖许可证，再输出单个 `.7z` 压缩包并检查完整性。LZMA2 高压缩率与固实压缩会增加打包耗时，解压后包含完整离线运行环境。同名输出已存在时直接报错，避免覆盖。
